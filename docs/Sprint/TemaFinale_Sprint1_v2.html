Goal

Realizzare il sottosistema minimo che gestisce l'accettazione/rifiuto di una richiesta di carico e la parte relativa al timeout dei 30 secondi. cargoservice riceve loadrequest, interroga Hold, risponde con loadaccepted/loadrejected, e passa da Idle a Engaged; se il timeout scade torna a Idle liberando lo slot.

Problem Analysis

Architettura logica del sottosistema

Rispetto al modello qak di Sprint0, in questo sprint restano solo l'attore cargoservice e gli oggetti Java che usa internamente (Hold, IOPortStatus). In questa fase del progetto, come già detto, ci occuperemo della logica di business e, pertanto, abbiamo scelto di rappresentare una classe IOPortStatus mock che simuli il comportamento dell'IOPort che andremo a sviluppare in futuro.

Modifiche alla classe Hold

Rispetto alla Hold dello Sprint0, sono state apportate delle modifiche:

  • E' stato modificato il metodo reserveFirstFree(). Per esigenze legate a semplicità, abbiamo scelto di cambiare il suo tipo, passando da String a int. A ogni slot è quindi associato un numero intero da 1 a 4 e il null è stato sostituito con un -1 simbolico.
  • Nella Hold di Sprint0 non era previsto liberare uno slot RESERVED. Serve però per gestire R2: se il cliente non porta il container entro un tempo prefissato (in questo caso 30s), lo slot prenotato deve tornare libero e lo stato disengaged, altrimenti la hold si "intaserebbe" di prenotazioni fantasma.
public class Hold {
    public static final int NUM_SLOTS = 4;       // slot1..slot4

    public enum SlotState { FREE, RESERVED, OCCUPIED }

    private SlotState[] slots = {
        SlotState.FREE,
        SlotState.FREE,
        SlotState.FREE,
        SlotState.FREE
    };

    private boolean slot5Occupied = false;

    public boolean isSlot5Occupied() {
        return slot5Occupied;
    }

    public void setSlot5Occupied(boolean occupied) {
        slot5Occupied = occupied;
    }

    public int reserveFirstFree() {
        for (int i = 0; i < NUM_SLOTS; i++) {
            if (slots[i] == SlotState.RESERVED) {
                return -1; // al più una prenotazione attiva alla volta
            }
        }
        for (int i = 0; i < NUM_SLOTS; i++) {
            if (slots[i] == SlotState.FREE) {
                slots[i] = SlotState.RESERVED;
                return (i + 1);
            }
        }
        return -1; // piena
    }

    public void markReservedOccupied() {
        for (int i = 0; i < NUM_SLOTS; i++) {
            if (slots[i] == SlotState.RESERVED) {
                slots[i] = SlotState.OCCUPIED;
                return;
            }
        }
    }

    public void releaseReserved() {
        for (int i = 0; i < NUM_SLOTS; i++) {
            if (slots[i] == SlotState.RESERVED) {
                slots[i] = SlotState.FREE;
                return;
            }
        }
    }

    public boolean isFull() {
        for (SlotState s : slots) {
            if (s != SlotState.OCCUPIED) {
                return false;
            }
        }
        return true;
    }

    public String displayStatus() {
        int occupied = 0;
        for (SlotState s : slots) {
            if (s == SlotState.OCCUPIED) {
                occupied++;
            }
        }
        return occupied + "/" + NUM_SLOTS + " occupied";
    }
}

IOPort

Nella prima versione di questo documento lo IOPort non esisteva come componente autonomo: cargoservice interrogava sincronamente un oggetto mock, IOPortStatus, per sapere se l'ingresso fosse occupato. Quella scelta andava bene per validare la logica di accettazione/rifiuto e il timeout, ma lasciava fuori dal modello il vero e proprio dispositivo fisico che il committente descrive nei requisiti (pulsante, sensore, display, LED). In questa sezione completiamo il sottosistema realizzando lo IOPort come QActor a sé stante, dotato di un pannello di controllo web che ne simula l'hardware.

Perché un attore e non più una chiamata sincrona

Far interrogare a cargoservice un oggetto IOPortStatus condiviso avrebbe funzionato anche per il dispositivo reale, ma avrebbe rotto il modello a scambio di messaggi che regge tutto il resto del sistema: due attori non devono condividere stato mutabile, altrimenti si reintroducono gli stessi problemi di concorrenza che il paradigma ad attori vuole evitare (accessi concorrenti, letture di valori non aggiornati, accoppiamento stretto fra le classi). Abbiamo quindi promosso IOPortStatus a stato interno dell'attore ioport: è ioport stesso, nel momento in cui riceve la pressione del pulsante, a leggere il proprio sensore e a inoltrare l'informazione a cargoservice come parametro del messaggio loadrequest. Nessuno dei due attori accede più allo stato interno dell'altro.

Lo IOPort deve esporre: un pulsante che genera la richiesta di carico, un sensore che rileva la presenza di un container, un display che mostra lo stato della hold e l'esito delle richieste, un LED che lampeggia mentre il sistema è engaged.

Protocollo dei messaggi aggiornato

Rispetto alla versione precedente, loadrequest porta ora il parametro OCCUPIED (letto dal sensore di ioport), e le risposte loadaccepted/loadrejected portano anche lo stato corrente della hold (HOLD), da mostrare sul display. Sono stati aggiunti tre nuovi Dispatch: pushButton e setOccupied arrivano dalla GUI verso ioport (simulano rispettivamente la pressione del pulsante e il sensore), mentre blinkLed ora viaggia da cargoservice a ioport invece che restare interno a cargoservice com'era nel mock.

Il modello qak completo

Di seguito il modello sprint1.qak aggiornato con entrambi gli attori. cargoservice è concettualmente lo stesso automa a stati della versione precedente, con le firme dei messaggi aggiornate e il forward di blinkLed diretto a ioport anziché a se stesso. L'attore ioport è nuovo: nello stato idle attende uno dei tre dispatch provenienti dalla GUI o da cargoservice; alla pressione del pulsante (onButtonPressed) legge status.isOccupied() e apre una request verso cargoservice; ricevuta la risposta (showAccepted/showRejected) aggiorna il display via wsAdapter; onSetOccupied aggiorna il sensore mock e lo notifica alla GUI; onBlinkLed pilota il LED e, quando il LED si spegne, aggiorna anche il display per segnalare che lo slot è stato liberato.

Il ponte WebSocket: IOPortWsAdapter

L'attore ioport non parla direttamente HTTP/WebSocket: la comunicazione con il browser è delegata a IOPortWsAdapter, istanziato una sola volta all'ingresso nello stato idle con # val wsAdapter = utils.cargoservice.IOPortWsAdapter(this, 7070) #. L'adapter incapsula un server Javalin che:

  • serve i file statici della GUI (ioport_gui.html, style.css, wscontrol.js) dalla cartella resources/page;
  • espone l'endpoint WebSocket /ws/ioport, a cui il browser si collega per inviare e ricevere eventi;
  • tiene traccia dei client connessi in un Set<WsContext> (un CopyOnWriteArraySet, per poter iterare in sicurezza anche se un client si connette o disconnette mentre si sta facendo il broadcast).

Il verso GUI → attore passa da handleClientMessage: il JSON ricevuto sul socket viene tradotto in un dispatch qak (toDispatch) e recapitato con sendMsgToMyself, cioè l'adapter si comporta come se fosse un mittente esterno che manda un messaggio a ioport. Il verso attore → GUI è invece costituito dai tre metodi pubblici (updateDisplay, setLed, notifySensor) richiamati dal corpo del qak, che serializzano lo stato in JSON e lo inviano in broadcast a tutti i client connessi.

package utils.cargoservice;

import java.util.Set;
import java.util.concurrent.CopyOnWriteArraySet;

import io.javalin.Javalin;
import io.javalin.http.staticfiles.Location;
import io.javalin.websocket.WsContext;
import it.unibo.kactor.ActorBasic;
import org.json.simple.JSONObject;
import org.json.simple.parser.JSONParser;
import unibo.basicomm23.interfaces.IApplMessage;
import unibo.basicomm23.utils.CommUtils;

public class IOPortWsAdapter {

    private static final String SENDER = "ioportws";
    private static final String IOPORT_NAME = "ioport"; // nome dell'attore nel .qak, non generico di proposito

    private final ActorBasic ioport;
    private final Set<WsContext> clients = new CopyOnWriteArraySet<>();

    public IOPortWsAdapter(ActorBasic ioport, int port) {
        this.ioport = ioport;

        var app = Javalin.create(config -> {
            config.staticFiles.add(staticFiles -> {
                staticFiles.directory = "/page";
                staticFiles.location = Location.CLASSPATH;
            });
        }).start(port);

        app.get("/", ctx -> ctx.redirect("/ioport_gui.html"));

        app.ws("/ws/ioport", ws -> {
            ws.onConnect(ctx -> {
                clients.add(ctx);
                CommUtils.outgreen("IOPortWsAdapter | client connected: " + ctx.session.getRemoteAddress());
            });
            ws.onClose(ctx -> {
                clients.remove(ctx);
                CommUtils.outyellow("IOPortWsAdapter | client disconnected");
            });
            ws.onMessage(ctx -> handleClientMessage(ctx.message()));
        });

        CommUtils.outgreen("IOPortWsAdapter | started on port " + port + " (gui: http://localhost:" + port + "/ioport_gui.html)");
    }

    private void handleClientMessage(String raw) {
        try {
            String[] dispatch = toDispatch(raw);
            sendToActor(dispatch[0], dispatch[1]);
        } catch (Exception e) {
            CommUtils.outred("IOPortWsAdapter | bad message from client: " + raw + " (" + e.getMessage() + ")");
        }
    }

    private void sendToActor(String msgId, String content) {
        IApplMessage dispatch = CommUtils.buildDispatch(SENDER, msgId, content, IOPORT_NAME);
        ioport.sendMsgToMyself(dispatch);
    }

    public void updateDisplay(String state, String hold, String msg) {
        broadcast(displayJson(state, hold, msg));
    }

    public void setLed(String onOff) {
        broadcast(ledJson(onOff));
    }

    public void notifySensor(String flag) {
        broadcast(sensorJson(flag));
    }

    private void broadcast(String json) {
        clients.forEach(ctx -> ctx.send(json));
    }


    static String[] toDispatch(String raw) throws Exception {
        JSONObject json = (JSONObject) new JSONParser().parse(raw);
        String type = (String) json.get("type");
        if ("pushButton".equals(type)) {
            return new String[] { "pushButton", "pushButton(0)" };
        } else if ("setOccupied".equals(type)) {
            boolean value = Boolean.TRUE.equals(json.get("value"));
            return new String[] { "setOccupied", "setOccupied(" + value + ")" };
        }
        throw new IllegalArgumentException("unknown message type: " + type);
    }

    static String displayJson(String state, String hold, String msg) {
        JSONObject json = new JSONObject();
        json.put("type", "display");
        json.put("state", state);
        json.put("hold", hold);
        json.put("msg", msg);
        return json.toJSONString();
    }

    static String ledJson(String onOff) {
        JSONObject json = new JSONObject();
        json.put("type", "led");
        json.put("on", "on".equals(onOff));
        return json.toJSONString();
    }

    static String sensorJson(String flag) {
        JSONObject json = new JSONObject();
        json.put("type", "sensor");
        json.put("occupied", "true".equals(flag));
        return json.toJSONString();
    }
}
Il timer dei 30 secondi è gestito lato server dall'automa cargoservice (whenTime 30000), ma per dare un riscontro visivo immediato la GUI avvia anche un proprio countdown locale (TIMER_SECONDS = 30 in wscontrol.js). I due timer non sono sincronizzati da nessun messaggio esplicito: nell'uso normale scadono praticamente insieme, ma un ritardo di rete o un refresh della pagina potrebbero disallinearli. È accettabile che il conteggio mostrato sul pannello sia puramente indicativo, oppure il countdown dovrebbe essere pilotato dal server (ad es. inviando il tempo residuo nel messaggio display)?

wscontrol.js è racchiuso in una IIFE — (function () { ... })() — proprio per non lasciare le variabili (socket, sensorOccupied, i riferimenti al DOM) nello scope globale della pagina: tutto lo stato del pannello resta privato al modulo, ed è visibile solo alle funzioni definite al suo interno. Lo script apre la connessione WebSocket, gestisce la riconnessione automatica in caso di caduta (onclose richiama connect dopo RECONNECT_MS), e traduce i messaggi JSON in aggiornamenti del DOM. Per LED e sensore si usa classList.toggle('on', condizione)/classList.toggle('occupied', condizione): passando un secondo argomento booleano, la classe CSS viene aggiunta o rimossa in base al valore, invece di essere semplicemente invertita a ogni chiamata — una singola riga che tiene sempre la vista sincronizzata con lo stato ricevuto dal server, anche se lo stesso messaggio arrivasse due volte.

(function () {
  const btn = document.getElementById('pushBtn');
  const sensorSwitch = document.getElementById('sensorSwitch');
  const led = document.getElementById('led');
  const stateVal = document.getElementById('stateVal');
  const holdVal = document.getElementById('holdVal');
  const msgVal = document.getElementById('msgVal');
  const connStatus = document.getElementById('connStatus');
  const timerVal = document.getElementById('timerVal');

  let sensorOccupied = false;
  let socket = null;
  const RECONNECT_MS = 2000;

  const TIMER_SECONDS = 30;
  let timerInterval = null;

  function startTimer() {
    let remaining = TIMER_SECONDS;
    timerVal.textContent = remaining + ' s';
    btn.disabled = true;

    clearInterval(timerInterval);
    timerInterval = setInterval(() => {
      remaining -= 1;
      if (remaining <= 0) {
        clearInterval(timerInterval);
        timerVal.textContent = '--';
        if (socket && socket.readyState === WebSocket.OPEN) {
          btn.disabled = false;
        }
        return;
      }
      timerVal.textContent = remaining + ' s';
    }, 1000);
  }

  function setConnStatus(text, lost) {
    connStatus.textContent = text;
    connStatus.style.color = lost ? '#e88' : '';
  }

  function setControlsEnabled(enabled) {
    btn.disabled = !enabled;
    sensorSwitch.disabled = !enabled;
  }

  function connect() {
    socket = new WebSocket('ws://' + window.location.host + '/ws/ioport');

    socket.onopen = () => {
      setConnStatus('connesso', false);
      setControlsEnabled(true);
    };

    socket.onmessage = (event) => {
      let msg;
      try {
        msg = JSON.parse(event.data);
      } catch (e) {
        console.warn('ioport_gui: messaggio non JSON ignorato:', event.data);
        return;
      }
      if (msg.type === 'display') {
        stateVal.textContent = msg.state;
        holdVal.textContent = msg.hold;
        msgVal.textContent = msg.msg;
      } else if (msg.type === 'led') {
        led.classList.toggle('on', !!msg.on);
      } else if (msg.type === 'sensor') {
        sensorOccupied = !!msg.occupied;
        sensorSwitch.classList.toggle('occupied', sensorOccupied);
        sensorSwitch.setAttribute('aria-pressed', String(sensorOccupied));
      }
    };

    socket.onclose = () => {
      setConnStatus('connessione persa, riprovo...', true);
      setControlsEnabled(false);
      setTimeout(connect, RECONNECT_MS);
    };

    socket.onerror = () => {
      socket.close();
    };
  }

  btn.addEventListener('click', () => {
    if (socket && socket.readyState === WebSocket.OPEN) {
      socket.send(JSON.stringify({ type: 'pushButton' }));
      startTimer();
    }
  });

  sensorSwitch.addEventListener('click', () => {
    if (!(socket && socket.readyState === WebSocket.OPEN)) return;
    sensorOccupied = !sensorOccupied;
    sensorSwitch.classList.toggle('occupied', sensorOccupied);
    sensorSwitch.setAttribute('aria-pressed', String(sensorOccupied));
    socket.send(JSON.stringify({ type: 'setOccupied', value: sensorOccupied }));
  });

  setControlsEnabled(false);
  connect();
})();

T1.6 Dopo reserveFirstFree(), una chiamata a releaseReserved() deve far tornare libero lo slot: una successiva reserveFirstFree() deve restituire lo stesso slot.

Riportiamo qui sotto la classe HoldTest modificata, in quanto sono stati modificati alcuni metodi nella classe Hold.

class HoldTest {

    Hold hold;

    @BeforeEach
    void setUp() { hold = new Hold(); }

    @Test // T1.1
    void reserveFromEmpty() {
        assertEquals(1, hold.reserveFirstFree());
    }

    @Test // T1.2
    void fullWhenAllOccupied() {
        for (int i = 0; i < Hold.NUM_SLOTS; i++) {
            hold.reserveFirstFree();
            hold.markReservedOccupied();
        }
        assertTrue(hold.isFull());
    }

    @Test // T1.3
    void reserveWhenFull() {
        for (int i = 0; i < Hold.NUM_SLOTS; i++) {
            hold.reserveFirstFree();
            hold.markReservedOccupied();
        }
        assertEquals(-1, hold.reserveFirstFree());
    }

    @Test // T1.4
    void markReservedBecomesOccupied() {
        hold.reserveFirstFree();
        hold.markReservedOccupied();
        assertFalse(hold.isFull()); // 1/4, non piena
        assertNotEquals(-1, hold.reserveFirstFree());
    }

    @Test // T1.5
    void noDoubleReserve() {
        hold.reserveFirstFree(); // slot1 → RESERVED
        assertEquals(-1, hold.reserveFirstFree());
    }

    @Test // T1.6 
    void releaseReservedFreesTheSlot() {
        hold.reserveFirstFree(); // slot1 -> RESERVED
        hold.releaseReserved();
        assertEquals(1, hold.reserveFirstFree());
    }
}
